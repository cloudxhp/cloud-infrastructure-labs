# Linux Logs and Journalctl

## Objective

Learn how Linux records system activity, service events, authentication attempts, kernel messages, and application logs.

Log analysis is one of the most important troubleshooting skills for:

* Linux Administration
* Cloud Support Engineering
* AWS Operations
* DevOps
* Site Reliability Engineering (SRE)

When services fail, logs often reveal the root cause.

---

# Why Logs Matter

Logs provide a historical record of system activity.

They help answer questions such as:

* Why did a service fail?
* Why can't users connect?
* What changed recently?
* Did the server reboot?
* Were there authentication failures?
* Is the application generating errors?

A common troubleshooting workflow is:

```text
Problem Reported
       ↓
Check Service Status
       ↓
Check Listening Ports
       ↓
Check Connectivity
       ↓
Check Logs
       ↓
Identify Root Cause
```

---

# Journalctl Overview

## Command

```bash
journalctl
```

## Purpose

Displays logs collected by systemd-journald.

Journalctl centralizes system logs from:

* Services
* Applications
* Kernel
* Boot processes
* Authentication events

---

# View Recent Log Entries

## Command

```bash
journalctl -n 20
```

## Purpose

Displays the most recent 20 log entries.

## Example Events

* System startup
* Service starts and stops
* Package updates
* Time synchronization events
* Network activity

## Troubleshooting Use

Useful when investigating:

* Recent failures
* Unexpected behavior
* System changes

---

# View Logs for a Specific Service

## Command

```bash
journalctl -u SERVICE_NAME
```

Example:

```bash
journalctl -u nginx
```

or

```bash
journalctl -u ssh
```

## Purpose

Displays logs generated by a specific service.

## Troubleshooting Use

Common services:

| Service | Purpose              |
| ------- | -------------------- |
| nginx   | Web server           |
| apache2 | Web server           |
| ssh     | Remote access        |
| docker  | Containers           |
| chronyd | Time synchronization |

Example:

```bash
journalctl -u nginx --no-pager -n 20
```

Displays the latest 20 Nginx log entries.

---

# View Boot History

## Command

```bash
journalctl --list-boots
```

## Purpose

Displays previous system boot sessions.

## Example

```text
IDX  BOOT ID
-2   Previous Boot
-1   Previous Boot
 0   Current Boot
```

## Key Concept

### Current Boot

```text
0
```

Represents the currently running session.

### Previous Boot

```text
-1
```

Represents the most recent completed session.

## Troubleshooting Use

Useful when:

* Diagnosing reboot issues
* Investigating startup failures
* Comparing current and previous sessions

---

# View Logs From Current Boot

## Command

```bash
journalctl -b
```

## Purpose

Displays logs from the current boot session only.

## Troubleshooting Use

Helps isolate events occurring since startup.

---

# View Logs From Previous Boot

## Command

```bash
journalctl -b -1
```

## Purpose

Displays logs from the previous boot session.

## Troubleshooting Use

Useful when investigating:

* Unexpected reboots
* Startup failures
* Crashes before restart

# Traditional Linux Log Files

Linux also stores logs in:

```bash
/var/log
```

View contents:

```bash
ls /var/log
```

---

# Important Log Files

## syslog

Location:

```bash
/var/log/syslog
```

Purpose:

General system activity.

Contains:

* Service events
* System messages
* Application activity

View recent entries:

```bash
tail -20 /var/log/syslog
```

---

## auth.log

Location:

```bash
/var/log/auth.log
```

Purpose:

Authentication and authorization activity.

Contains:

* Login attempts
* SSH access
* Sudo usage
* User authentication events

Useful for security investigations.

---

## kern.log

Location:

```bash
/var/log/kern.log
```

Purpose:

Kernel messages.

Contains:

* Hardware events
* Driver messages
* Kernel warnings
* System-level issues

---

## dpkg.log

Location:

```bash
/var/log/dpkg.log
```

Purpose:

Package installation history.

Contains:

* Installed packages
* Removed packages
* Upgrades
* Updates

Useful when tracking system changes.

---

## wtmp

Location:

```bash
/var/log/wtmp
```

Purpose:

Records successful logins and system boots.

View using:

```bash
last
```

---

## btmp

Location:

```bash
/var/log/btmp
```

Purpose:

Records failed login attempts.

View using:

```bash
sudo lastb
```

Useful for security monitoring.

---

# Viewing Recent Log Entries

## Command

```bash
tail -20 /var/log/syslog
```

## Purpose

Displays the newest 20 entries in the syslog file.

## Troubleshooting Use

Quickly identify:

* Recent errors
* Service restarts
* System events
* Configuration problems

# Real-World Troubleshooting Examples

## Nginx Website Not Loading

Check:

```bash
systemctl status nginx
```

Then:

```bash
journalctl -u nginx
```

Look for:

* Configuration errors
* Port conflicts
* Permission issues

---

## SSH Access Failure

Check:

```bash
journalctl -u ssh
```

and

```bash
tail -20 /var/log/auth.log
```

Look for:

* Authentication failures
* Invalid credentials
* Permission problems

---

## Unexpected Reboot

Check:

```bash
journalctl --list-boots
```

Then:

```bash
journalctl -b -1
```

Look for:

* Kernel crashes
* Resource exhaustion
* Service failures

# Key Takeaways

* Logs record system activity and historical events.
* Journalctl is the primary tool for viewing systemd logs.
* Service-specific logs help diagnose application failures.
* Boot logs help investigate startup issues.
* Syslog contains general system activity.
* Auth.log contains login and authentication events.
* Logs are often the fastest path to identifying root causes.
* Effective troubleshooting follows a structured process:

  * Check service
  * Check ports
  * Check connectivity
  * Check logs
  * Resolve root cause

Log analysis is a core skill for Linux Administrators, Cloud Support Engineers, DevOps Engineers, and Cloud Engineers.
